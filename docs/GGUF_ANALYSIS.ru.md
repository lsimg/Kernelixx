# SmolLM2: разбор результата и следующие проверки

## Что установил этот запуск

На одном и том же файле модели сравнили один и четыре потока процессора.
Использовались три вопроса, по пять измеренных повторов каждого в каждом режиме.
Модель, вопросы и настройки генерации совпадали. Перед измерениями был прогрев.

| Показатель | Один поток | Четыре потока |
|---|---:|---:|
| Медианное время ответа | 522,105 мс | 241,760 мс |
| Время до первого токена | 238,313 мс | 89,561 мс |
| Скорость продолжения ответа | 58,801 токена/с | 118,565 токена/с |
| Замеченная память процесса | 194,137 МиБ | 195,820 МиБ |

В этом наборе измерений переход к четырём потокам сократил медианную задержку
на **280,345 мс, или 53,70%**. Память процесса выросла примерно на **1,684 МиБ**.
Ответы сохранились на уровне последовательностей токенов.

Ускорение видно для каждого вопроса отдельно:

| Вопрос | Один поток | Четыре потока | Отношение задержек |
|---|---:|---:|---:|
| Объяснить нейросеть | 875,463 мс | 408,725 мс | 2,142 |
| Посчитать 7 + 5 | 407,580 мс | 176,128 мс | 2,314 |
| Назвать три фрукта | 522,105 мс | 241,760 мс | 2,160 |

Таким образом, четыре потока — обоснованный кандидат для следующего раунда
проверок. Результат даёт отправную точку для выбора настроек под разные запросы.

## Какие решения помогут принять следующие эксперименты

| Следующая проверка | Что именно сделать | Какое решение она обоснует |
|---|---|---|
| Повторяемость | Провести независимые пары запусков, чередуя порядок 1/4 и 4/1, повторить в другой сессии | Насколько устойчив выигрыш и какую настройку рекомендовать |
| Число потоков | Сравнить 1, 2, 4 и 8, где позволяет процессор | Какое количество потоков лучше подходит конкретной нагрузке |
| Длина текста | Проверить короткие и длинные вопросы и ответы | Как меняется время начала ответа, скорость продолжения и память |
| Правильность и формат | Заранее подготовить вопросы с правильными ответами и правилами оформления | Насколько хорошо модель решает задачу и выполняет инструкции |
| Память по этапам | Разделить загрузку, обработку вопроса и генерацию, проверить частоту измерений | Какой запас памяти нужен при разных настройках |
| Варианты точности | Сравнить F16/Q8/Q4, полученные из одинаковых исходных весов | Как выбрать соотношение размера, скорости и качества |
| Видеокарта | Подтвердить работу отдельного GPU-модуля и метод измерения его памяти | Для каких запросов полезен запуск на GPU |

Подробный план определяет порядок экспериментов, сохраняемые данные и критерии
решения. Это **запланированные проверки**, а таблицы выше рассчитаны из уже
сохранённого запуска. Новые испытания при подготовке этого разбора не выполнялись.

## Почему качество ответов проверяется отдельно

На вопрос о 7 + 5 модель получила правильную сумму, но добавила текст вместо
запрошенного единственного числа. Фрукты перечислены списком вместо строки
через запятую. Эти наблюдения дают конкретные примеры для двух оценок:

- **Содержание:** верен ли ответ по смыслу.
- **Формат:** соблюдено ли требование пользователя.

Совпадение токенов подтверждает, что два режима воспроизвели одинаковые ответы.
Подписанный набор задач позволит дополнить эту проверку оценками содержания
и формата, с заранее определёнными правилами.

## Как сохраняется воспроизводимость

Исходные JSON, CSV и автоматически сформированный отчёт сохранены без изменений.
Дополнительный [анализ JSON](experiments/smollm2-135m-q4-cpu/analysis.json) содержит
контрольную сумму исходного отчёта и вычисленные показатели; [CSV по вопросам](experiments/smollm2-135m-q4-cpu/per-prompt.csv)
показывает оба режима отдельно. Это позволяет проверить выводы по исходным данным.

Текущие цифры относятся к CPU и уже квантованному файлу Q4_K_M. Память здесь —
наблюдаемый рабочий набор процесса. Для сравнения вариантов точности и GPU
предусмотрены собственные опорные модели и методы измерения.
