## Что делает memory-оптимизация SoupLite

Изучены `solution/chunked_head.py`, `fused_ce.py`, точки подключения, тесты и
официальный harness. Основная задача — Qwen SFT/LoRA с большим словарём:

1. Проекция LM head и CE выполняются блоками по 256 позиций вместо удержания
   всего массива `[B,T,V]`.
2. Кешируются вычисленные entropy, argmax и token loss размера `[B,T]`.
3. В backward повторно вычисляются проекция и CE блока. Это экономия сохранённых
   активаций обучения, а не основание включать recomputation в обычный inference.
4. Используется общий знаменатель по валидным токенам, включая последний блок;
   средние блоков нельзя просто усреднить при разных размерах и масках.
5. Оптимизация ограничена замороженным head, определённым Qwen/TRL/Soup/AMP
   контрактом. Неподдерживаемые случаи используют исходный путь. Lazy logits —
   специальный интерфейс известных потребителей, а не универсальная замена Tensor.
6. Контекст изменения поведения восстанавливается через `finally`; временные
   buffers принадлежат вызову. Глобальный переиспользуемый scratch не нужен.
7. Сохранённые проверки связаны с хешами результатов и исходников; изменённый код
   делает старые checks устаревшими.

## Сохранённые измерения и их границы

| Историческая T4-серия | Полное время baseline → solution, с | Training loop, с | GPU peak, MiB |
|---|---:|---:|---:|
| Original | 84,41 → 83,11 | 59,03 → 61,42 | 14 345 → 8 603 |
| Additional | 83,93 → 78,82 | 56,82 → 57,26 | 14 345 → 8 603 |

Уменьшение сохранённого пика — 40,027884%. Оно относится к комбинации SoupLite
и starter SwiGLU, а не к отдельному перенесённому приёму. Training loop в обеих
сериях стал медленнее, несмотря на меньшее полное время. Внешний GPU peak harness
получает через `nvidia-smi`; PyTorch allocated/reserved сохраняются отдельно.
Эти значения не смешиваются с метриками Kernelixx.

Полное обучение здесь не повторялось: требуются другой закреплённый стек и
Triton, которого нет в текущем окружении; сохранённый solution peak 8603 MiB
превышает объём памяти RTX 4060 Laptop этого компьютера. **T4/GPU-перенос не
подтверждён.** После чтения соответствующего кода выполнены только выбранные
CPU-проверки chunked loss: **9 passed, 2 deselected**. Это математика loss/метрик,
производных, масок и хвостовых блоков; это не GPU speedup.

## Применимость к Kernelixx

| Приём | Решение |
|---|---|
| Потоковые блоки и компактные накопители метрик | Соответствуют уже добавленным BatchSource и ValidationAccumulator; архитектуру сохраняем |
| Взвешенная агрегация и хвостовой блок | Существующие проверки Kernelixx сохраняются; результаты считаются по элементам/примерам, не по средним batch |
| Пересчёт LM head в backward | Не переносится в ResNet/GGUF inference; отдельного совместимого обучения Qwen здесь нет |
| Lazy logits / глобальные Qwen hooks | Не переносится: текущий Runner требует Tensor; выводы и consumers отличаются |
| CE/RMSNorm/cast Triton kernels | Не переносятся без подходящего bottleneck, совместимого runtime и новых численных/GPU-тестов |
| Контроль устаревания checks по исходникам | Применён точечно к источникам модели, экспортируемому runtime и независимым повторам |

## Подтверждённый дополнительный дефект и исправление

До исправления новый regression test менял только `forward` пользовательской
модели, сохраняя все веса и их SHA-256. Экспорт ошибочно принимал модель: он
сравнивал новый runner с заново созданной, уже изменённой reference-моделью.
Тест воспроизвёл отсутствие ожидаемого отклонения. Лог —
`results/source-provenance-before.txt`.

Теперь `load_model` записывает отпечатки Python-пакета Kernelixx, модуля фабрики
и модулей классов `nn.Module`. Экспорт сопоставляет их с сохранённым опытом;
PyTorch runtime recipe проверяет их также при reload. Независимые worker проверяют
одинаковый digest исходников в каждом прогоне. ONNX остаётся самостоятельным
артефактом: изменение доступности Python-фабрики не должно запрещать загрузку
уже экспортированного графа с корректной контрольной суммой.

Старые отчёты читаются и экспортируются как прежде, но проверка их исторического
кода явно получает `NOT VERIFIED`. Новые артефакты фиксируют исходники текущего
runtime. Это не полный dependency closure: произвольные imported helpers,
runtime monkeypatch, native-библиотеки и внешнее состояние не доказываются этим
digest. Версии библиотек, state/dataset hashes и численная проверка остаются
отдельными проверками. Код и kernels SoupLite в Kernelixx не копировались.

**127 тестов прошли, без пропусков**: полный прежний набор и новые проверки
изменённого forward при неизменных весах, отклонения изменённого кода при reload
и явного статуса старых отчётов. Реальные CUDA/ONNX/GGUF проверки сохранены.
[Лог](test-results-souplite-followup.txt). Отдельно пройдены 9 CPU-тестов
из прочитанного SoupLite-пакета ([лог](test-results-souplite-reference.txt)).

не выдаются за новые измерения после этой правки.
